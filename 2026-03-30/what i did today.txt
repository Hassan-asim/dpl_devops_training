In addition to gathering configuration information, you will need diagnostic data from log files for troubleshooting.

Where are the Amazon ECS log files located?

Amazon ECS stores logs in the /var/log/ecs folder of your container instances. There are logs available from the Amazon ECS container agent and from the ecs-init service that controls the state of the agent (start/stop) on the container instance. You can access these log files by connecting to a container instance using Secure Shell (SSH). 



Screenshot of a terminal session to the local system that shows the location of the ECS Agent log files.

What are other log files I can use?

The Amazon ECS container agent stores logs on your container instances. There are two log files:

ecs-agent.log.[time stamp]
ecs-init.log.[time stamp]
For more information about log entries and examples, see Amazon ECS Log File Locations(opens in a new tab).

How can I collect these logs for further analysis?

If you need to submit a support ticket to Support, you can collect all of the logs on your container instances by using the Amazon ECS logs collector. # MR: Automate Stop/Start of `db-bastion` EC2 Instance via CDK + SSM

## Objective

Automate lifecycle management of the `db-bastion` EC2 instance:

* Stop the instance daily at midnight (PKT)
* Start the instance daily at a defined time (e.g., morning)

---

## Approach

Use AWS CDK with:

* Amazon EventBridge for scheduling
* AWS Systems Manager Automation with AWS-managed runbooks:

  * `AWS-StopEC2Instance`
  * `AWS-StartEC2Instance`

---

## Implementation Plan

### 1. Identify Target Instance

* Retrieve the EC2 **Instance ID** for `db-bastion`

---

### 2. Create CDK Stack

Add a new stack:

```ts
db-bastion-schedule-stack
```

---

### 3. Configure IAM Role

Create a role for EventBridge to trigger SSM Automation with permissions:

* `ssm:StartAutomationExecution`
* `ec2:StopInstances`
* `ec2:StartInstances`

---

### 4. Create Stop Schedule

* EventBridge cron (PKT midnight → UTC):

```ts
cron(0 19 * * ? *)
```

* Target:

  * SSM Document: `AWS-StopEC2Instance`
  * Parameter:

```ts
InstanceId = <db-bastion-instance-id>
```

---

### 5. Create Start Schedule

* Example start time: 9 AM PKT → 04:00 UTC

```ts
cron(0 4 * * ? *)
```

* Target:

  * SSM Document: `AWS-StartEC2Instance`
  * Parameter:

```ts
InstanceId = <db-bastion-instance-id>
```

---

### 6. Link Components

* EventBridge rules use IAM role
* Each rule triggers corresponding SSM Automation document

---

### 7. Deploy

```ts
cdk deploy
```
